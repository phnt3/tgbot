# PC Remote

Telegram-бот для удалённого наблюдения за компьютером и управления им под Windows 11.
Написан на Python 3.12 и aiogram 3. Все действия доступны только пользователям из
белого списка; произвольные команды, пути и процессы из Telegram выполнить нельзя.

---

## Возможности

- **Мониторинг системы**: CPU (загрузка, частота, температура, ядра), RAM, GPU
  (NVIDIA через NVML: загрузка, температура, VRAM, мощность), диски, uptime,
  доступность интернета.
- **Скриншот рабочего стола** по запросу (PNG).
- **Запуск приложений** только из настраиваемого белого списка, с проверкой
  существования файла и защитой от повторного запуска.
- **Игровые профили** GAMING / VR / WORK / NORMAL: запуск набора приложений
  (обязательных и опциональных) одним нажатием.
- **Питание**: блокировка, сон, гибернация, выключение экрана, перезагрузка,
  выключение, отмена выключения.
- **Завершение процессов** только из белого списка, с защитой критических
  процессов Windows и повторной проверкой PID.
- **Фоновый монитор**: периодический сбор метрик, запись истории в SQLite,
  алерты при превышении порогов, уведомления о восстановлении.
- **История алертов** и **графики** за 5 минут, час и 24 часа.
- **Файлы**: просмотр папок, скачивание файлов до 45 МБ, загрузка
  документов/фото до 20 МБ в `data/uploads` и поиск по именам файлов и папок
  внутри текущего каталога.
- **Буфер обмена**: чтение текста с ПК в Telegram, запись текста из Telegram
  в буфер обмена Windows и очистка буфера.
- **Дисковое пространство**: обзор томов, анализ временных и кэш-папок,
  очистка с подтверждением, размер и очистка корзины.
- **Звук и медиа**: громкость, mute, play/pause, предыдущий/следующий трек, стоп.
- **Сеть / VPN**: активные интерфейсы, Wi-Fi (SSID, сигнал), VPN и публичный IP.
- **Уведомления с ПК**: вход в систему, низкий заряд батареи, завершение или
  падение приложений из белого списка.
- **Планировщик**: отложенные выключение, перезагрузка, сон, блокировка и запуск
  профиля; задачи сохраняются между перезапусками бота.
- Все сообщения бота — обычный текст без Markdown, поэтому специальные символы
  в именах процессов/приложений не ломают отправку.

## Требования

- Windows 11 (используются `shutdown`, `rundll32`, Windows API).
- Python 3.12.
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather).
- Свой Telegram user ID (например, через [@userinfobot](https://t.me/userinfobot)).
- Для GPU-метрик — видеокарта NVIDIA с установленным драйвером (необязательно;
  без неё GPU-поля будут `N/A`, остальное продолжит работать).

Зависимости (`requirements.txt`):

```
aiogram>=3.0
python-dotenv
psutil
nvidia-ml-py
matplotlib
```

`Pillow` (скриншоты) и `numpy` (графики) устанавливаются как зависимости matplotlib.

## Установка

Откройте PowerShell в каталоге проекта (`C:\tgbot`):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

> Если PowerShell блокирует активацию, выполните для текущего пользователя:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Либо не активируйте
> окружение и вызывайте Python напрямую: `.\.venv\Scripts\python.exe ...`.

### Настройка `.env`

Скопируйте шаблон и заполните значения:

```powershell
Copy-Item .env.example .env
notepad .env
```

```dotenv
BOT_TOKEN=123456789:AA...ваш_токен
ALLOWED_USER_IDS=111111111,222222222
```

- `BOT_TOKEN` — обязателен. Без него бот завершится с ошибкой конфигурации.
- `ALLOWED_USER_IDS` — список Telegram user ID через запятую. Пустой список
  означает, что бот отклонит **всех** пользователей (в лог будет предупреждение).
- `.env` содержит секреты и исключён из git (`.gitignore`). Не публикуйте его.

Файл `.env` читается при каждом импорте `config.py` с `override=True`, поэтому
после изменения значений перезапустите бота.

### Запуск

```powershell
.\.venv\Scripts\python.exe main.py
```

Или с активированным окружением:

```powershell
python main.py
```

При старте создаются каталоги `data/` и `logs/`, база `data/pc_remote.db`,
лог `logs/bot.log`. Остановка — `Ctrl+C`.

## Настройка белых списков

Списки приложений, профили, пороги алертов и уведомления хранятся в базе
`data/pc_remote.db` и редактируются прямо в боте: **Settings**. JSON-файлы
из `config/` используются только при первом запуске как начальные значения;
после него изменения в них на бота не влияют. Резервная копия настроек
экспортируется и импортируется отдельным JSON-файлом через бота.

### Приложения — `config/applications.json`

Формат: `"ключ": "полный путь к .exe"`.

```json
{
  "notepad": "C:\\Windows\\notepad.exe",
  "calculator": "C:\\Windows\\System32\\calc.exe",
  "steam": "C:\\Program Files (x86)\\Steam\\steam.exe"
}
```

- `config/applications.json` — **локальный** файл. Он добавлен в `.gitignore`
  и не публикуется в репозитории; в git хранится только
  `config/applications.example.json`.
- Ключ — имя, которое видно в меню и используется в профилях.
  Допустимы буквы, цифры, пробел, `.`, `-`, `_`, `+`.
- Путь должен быть абсолютным и не содержать `..`, `;`, `&`, `|`, `` ` ``,
  `<`, `>`. Квадратные скобки в путях допустимы (например,
  `Example Game [Build 1]`).
- Если файла нет, в меню приложение помечается `!`, запуск вернёт ошибку.
- Если `config/applications.json` отсутствует при первом запуске, берётся
  `config/applications.example.json`. Дальше список живёт в базе и правится
  в **Settings** (добавление, переименование, удаление, выбор `.exe`/`.lnk`).
- Запуск выполняется через `subprocess`/`os.startfile` напрямую, без shell,
  поэтому аргументы и произвольные команды передать нельзя.

### Профили — `config/profiles.json`

```json
{
  "GAMING": {
    "description": "Gaming profile",
    "apps": ["steam"],
    "optional": []
  },
  "WORK": {
    "description": "Work profile",
    "apps": ["notepad"],
    "optional": []
  },
  "NORMAL": {
    "description": "Status only",
    "apps": [],
    "optional": []
  }
}
```

- `config/profiles.json` — **локальный** файл, добавлен в `.gitignore`.
  В репозитории хранится только `config/profiles.example.json`.

- `apps` — обязательные приложения, `optional` — опциональные. Оба списка
  содержат **ключи** из `applications.json`.
- Приложения запускаются по очереди; уже запущенные пропускаются с сообщением
  «already running». Результат по каждому пункту показывается в чате.
- `NORMAL` ничего не запускает — показывает текущий статус системы.
- Профили не убивают процессы и не меняют настройки Windows.
- При первом запуске без `config/profiles.json` берётся пример; затем профили
  хранятся в базе и редактируются в **Settings** (создание, изменение состава,
  удаление).

### Алерты — `config/alerts.json`

```json
{
  "interval_seconds": 60,
  "thresholds": {
    "cpu_temperature": 80,
    "gpu_temperature": 80,
    "ram_utilization": 85,
    "disk_utilization": 85
  },
  "cooldowns": {
    "cpu_temperature": 300,
    "gpu_temperature": 300,
    "ram_utilization": 600,
    "disk_utilization": null
  }
}
```

| Ключ | Смысл | По умолчанию |
|---|---|---|
| `interval_seconds` | Период фонового опроса, секунды (допустимо 15–86400) | `60` |
| `thresholds.cpu_temperature` | Порог температуры CPU, °C | `80` |
| `thresholds.gpu_temperature` | Порог температуры GPU, °C | `80` |
| `thresholds.ram_utilization` | Порог загрузки RAM, % | `85` |
| `thresholds.disk_utilization` | Порог заполнения диска, % | `85` |
| `cooldowns.*` | Минимальный интервал повторного алерта, секунды; `null` — без повторов | `300` / `600` / `null` |

- Алерт создаётся при **переходе** через порог, а не на каждом опросе.
  Пока значение остаётся выше порога, повторные уведомления приходят не чаще
  указанного cooldown. При `null` повтор не приходит вовсе: пока диск не
  освободится и снова не заполнится, сообщение будет только одно.
- Восстановление фиксируется, когда значение падает на 2 °C / 2 п.п. ниже
  порога — так метрика, стоящая ровно на пороге, не «мигает».
- При температуре на 10 °C выше порога алерт помечается как критический.
- Диски проверяются отдельно по каждому тому (`disk_utilization:C:` и т. д.).
- Некорректные значения в JSON игнорируются с предупреждением в логе — бот
  продолжает работать на значениях по умолчанию.
- При первом запуске без `config/alerts.json` берутся значения по умолчанию.
  Дальше пороги, cooldown и интервал опроса хранятся в базе и меняются в
  **Settings**; JSON-файл нужен только для начального заполнения и импорта.

### Команды

| `/start` | Главное меню |
| `/help` | Справка по возможностям |
| `/status` | Полный снимок метрик системы |

### Главное меню

| Раздел | Что делает |
|---|---|
| System Monitoring | CPU, RAM, GPU, диски, uptime, интернет |
| Launch Applications | Список приложений и кнопки запуска |

| Power Management | Блокировка, сон, гибернация, выключение экрана, перезагрузка, выключение, отмена |
| Screenshot | Снимок рабочего стола |
| Running Processes | Топ-10 по CPU и по RAM |

| Charts | Графики CPU/GPU/RAM/Disk за 5m / 1h / 24h |

| Disk Space | Занятость дисков, анализ и очистка temp/cache, корзина |

### Питание

- **Lock** и **Sleep** выполняются сразу.
- **Hibernate** сохраняет сессию на диск и выключает ПК; после включения
  открытые окна и приложения восстанавливаются. Кнопка показывается только
  если гибернация разрешена в Windows.
- **Display Off** сразу гасит монитор; ПК и бот продолжают работать.
- **Restart** и **Shutdown** требуют второго нажатия **Confirm** в течение
  60 секунд. После подтверждения Windows выполняет действие с задержкой
  30 секунд — в это время работает **Cancel Shutdown**.
- Кнопка подтверждения одноразовая: повторное нажатие или устаревшая кнопка
  не запустят действие второй раз.
- **Cancel Shutdown** также сбрасывает ожидающие подтверждения.

### Процессы

- Показываются топ-10 процессов по CPU и по RAM.
- Метка `[K]` означает, что процесс можно завершить из бота.
- Завершение разрешено только для процессов, чьи `.exe` входят в
  `applications.json`, плюс `taskmgr.exe` и `notepad++.exe`.
- Критические системные процессы (`explorer.exe`, `winlogon.exe`, `csrss.exe`,
  `lsass.exe`, `services.exe`, `svchost.exe`, `System`, `Registry` и др.)
  запрещены всегда, даже если попадут в конфиг.
- Нажатие **Kill** открывает экран подтверждения; после **Confirm** PID
  проверяется повторно (имя, белый список, критичность), чтобы не убить
  процесс, получивший тот же PID после перезапуска.
- Завершение необратимо: несохранённые данные приложения будут потеряны.

### Скриншоты

- Снимок делается только по нажатию кнопки, автоматической съёмки нет.
- Основной способ — `PIL.ImageGrab`, резервный — GDI через Windows API.
- При заблокированном рабочем столе снимок может быть недоступен или пустым.
- Поддерживается High-DPI (изображение в полном разрешении).

### Графики

- Строятся по истории из SQLite: CPU (загрузка/температура/частота),
  GPU (загрузка/температура/VRAM/мощность), RAM, диск (самый загруженный том).
- Диапазоны: последние 5 минут, час, 24 часа.
- История пишется фоновым монитором раз в `interval_seconds`, поэтому сразу
  после запуска график может быть пустым.
- PNG отправляется в чат; рендеринг выполняется в отдельном потоке и не
  блокирует бота.

### Файлы

- **Files** открывает домашнюю папку; дальше — переход по каталогам кнопками
  (по 8 записей на страницу), **Up**, **Home**, **Refresh**.
- **Search this folder** ищет файлы и папки по имени внутри текущей папки,
  включая вложенные каталоги. Введите фрагмент имени (`video`) или маску
  (`*.mp4`, `report_?.pdf`) следующим сообщением. Поиск не учитывает регистр,
  ограничен глубиной 4 уровня, 2 000 папок и 8 секундами; найдётся не более
  30 совпадений. Результаты листаются по 8, нажатие на папку открывает её,
  нажатие на файл отправляет файл в чат. Запрос действует 5 минут.
- Кнопка файла отправляет его в чат (ограничение Telegram — 45 МБ).
- Документ или фото, отправленные боту, сохраняются в `data/uploads`
  (лимит 20 МБ). Имя очищается от недопустимых символов, существующие файлы
  не перезаписываются — добавляется суффикс `_1`, `_2` и т. д.
- Произвольные пути из чата не принимаются: навигация только по кнопкам,
  начиная с домашней папки.

### Буфер обмена

- **Clipboard → Read** присылает текущий текст из буфера обмена Windows.
  Текст показывается как есть, без Markdown-разметки; в чат выводится первые
  3 500 символов, полный лимит — 200 000 символов.
- **Clipboard → Write** включает ожидание: следующее текстовое сообщение
  заменяет содержимое буфера обмена на ПК. Запрос действует 5 минут, пустое
  сообщение не меняет буфер. **Cancel** отменяет ввод.
- **Clipboard → Clear** очищает буфер обмена; действие выполняется сразу.
- Буфер обмена общий для всех приложений Windows, поэтому запись заменяет
  то, что было скопировано ранее.
- Функция работает только на Windows; на других системах экран покажет,
  что мост недоступен. Изображения и файлы не поддерживаются — только текст.

### Дисковое пространство

- **Disk Space** показывает все фиксированные тома: свободно/всего и процент.
- **Analyze temp & cache** измеряет `%TEMP%`, `C:\Windows\Temp`, кэш Windows
  Update и другие известные папки. Скан ограничен по времени, поэтому очень
  большие каталоги могут быть помечены `scan truncated`.
- **Clean temp & cache** удаляет только содержимое временных и кэш-папок,
  без перехода по символическим ссылкам; перед удалением требуется **Confirm**
  в течение 60 секунд. Кэш Windows Update только показывается, но не чистится.
- **Recycle Bin** показывает размер корзины и позволяет очистить её после
  подтверждения. Очистка корзины необратима.

### Звук и медиа

- Кнопки **Vol -**, **Mute**, **Vol +** шлют стандартные мультимедиа-клавиши
  Windows (шаг громкости 2%).
- **Prev**, **Play/Pause**, **Next**, **Stop** действуют на активную
  медиа-сессию (браузер, плеер и т. п.).
- Действие применяется к текущей интерактивной сессии пользователя, поэтому
  при заблокированном экране результат может быть не виден.

### Сеть и VPN

- Показываются активные интерфейсы с IPv4-адресами и скоростью.
- VPN определяется по имени интерфейса (WireGuard, OpenVPN, TAP/TUN, Wintun
  и др.); выводится `VPN: ACTIVE` со списком адресов или `not detected`.
- Для Wi-Fi показываются SSID, уровень сигнала и тип аутентификации.
- Публичный IP запрашивается с внешнего сервиса (до 3 секунд); при отсутствии
  интернета выводится `unavailable`.

### Уведомления с ПК

Фоновый монитор раз в `interval_seconds` проверяет события и присылает их в
Telegram; они также записываются в **Alerts & History**:

- **Вход в систему** — новый пользователь в `psutil.users()`.
- **Батарея** — предупреждение при 20% и критическое при 10%; повторное
  уведомление возможно только после заряда выше порога + 5%.
- **Завершение приложения** — приложение из `applications.json` исчезло из
  списка процессов (cooldown 5 минут).
- **Падение приложения** — в процессах появился `WerFault.exe`
  (cooldown 10 минут).

Первый опрос после запуска только запоминает состояние, поэтому перезапуск бота
не создаёт ложных уведомлений.

### Планировщик

- **Scheduled Tasks** показывает задачи с обратным отсчётом и кнопками отмены.
- Быстрые действия: выключение через 15 / 30 / 60 минут, перезагрузка и сон
  через 30 минут, блокировка через 15 минут, запуск профилей GAMING и WORK
  через 30 минут.
- Допустимые действия ограничены: `shutdown`, `restart`, `sleep`, `lock`,
  `profile`. Произвольные команды запланировать нельзя.
- Задачи хранятся в `data/scheduled_tasks.json` и переживают перезапуск бота.
  Просроченные более чем на 2 минуты задачи при загрузке отбрасываются, чтобы
  бот не выключил ПК неожиданно после долгого простоя.
- Выполнение задачи приходит в чат отдельным сообщением; при ошибке — с текстом
  ошибки.

### Настройки в боте

Кнопка **Settings** открывает все настройки. Изменения применяются сразу,
перезапуск не нужен.

- **Notifications** — включение и выключение типов событий, пороги батареи,
  интервалы повторов для приложений и падений, тихие часы. В тихие часы
  приходят только критичные уведомления (батарея).
- **Monitoring alerts** — пороги CPU/GPU/RAM/диска, интервал опроса и
  cooldown. Время вводится в минутах: `0` — сообщать при каждой проверке,
  **Never repeat** — одно уведомление на одно превышение.
- **Applications** — добавить, переименовать или удалить приложение; путь
  выбирается кнопками по папкам либо вводится вручную (`.exe`/`.lnk`).
- **Gaming profiles** — создать профиль, изменить состав и удалить его.
- **Backup & restore** — экспорт настроек в JSON в этот чат, импорт файла
  (только после нажатия **Import settings**) и сброс к значениям из `config/`.
- Доступ (`ALLOWED_USER_IDS`) меняется только в `.env`; из бота это запрещено.
- Настройки лежат в `data/pc_remote.db`. JSON-бэкап содержит пути и списки
  приложений, поэтому его не стоит публиковать.

## Безопасность

Модель безопасности рассчитана на то, что бот доступен из интернета через
Telegram, а не по локальной сети.

1. **Белый список пользователей.** Команды и inline-кнопки проверяют
   `ALLOWED_USER_IDS`. Пересланное сообщение с кнопками не даёт чужому аккаунту
   управлять ПК: авторизация выполняется и в обработчике callback.
2. **Нет произвольных команд.** Из Telegram нельзя передать shell-команду,
   аргументы, путь или произвольный PID для запуска.
3. **Белый список приложений.** Запускаются только записи из
   `config/applications.json`, прошедшие валидацию имени и пути.
4. **Белый список процессов.** Завершать можно только allowlist-приложения и
   две утилиты; критические процессы Windows защищены отдельно.
5. **Двойное подтверждение.** Выключение, перезагрузка и kill требуют
   подтверждения в течение 60 секунд; состояние одноразовое.
6. **Задержка Windows.** Выключение/перезагрузка идут с `/t 30`, чтобы
   оставалась возможность отмены.
7. **Повторная проверка PID.** Перед kill процесс проверяется заново.
8. **Плейн-текст.** Бот не использует `parse_mode`, поэтому содержимое не
   интерпретируется как разметка Telegram.
9. **Логи.** Все действия и ошибки пишутся в `logs/bot.log`.

Ограничения, которые стоит понимать:

- Токен бота — это полный доступ к боту. При утечке немедленно перевыпустите
  его в @BotFather.
- `ALLOWED_USER_IDS` защищает управление, но не шифрует переписку с Telegram.
- Бот должен работать под учётной записью пользователя, который имеет право
  выключать компьютер и делать скриншоты. Запуск от администратора не требуется.
- Не запускайте два экземпляра одновременно: Telegram вернёт конфликт
  `getUpdates` и один из процессов будет постоянно перезапускаться.

## Данные и логи

- `data/pc_remote.db` — SQLite. Таблицы:
  `measurements`, `alerts`, `app_launches`, `system_status`,
  `cpu_history`, `gpu_history`, `ram_history`, `disk_history`,
  `process_snapshots`.
- `data/scheduled_tasks.json` — отложенные задачи планировщика (ID, действие,
  время запуска, параметры). Запись атомарная, через временный файл.
- `data/uploads/` — файлы, отправленные боту из Telegram.
- История метрик обрезается до 10 000 строк на таблицу (проверка раз в
  60 циклов фонового монитора).
- `logs/bot.log` — журнал приложения (уровень INFO, формат
  `время - модуль - уровень - сообщение`). Файл не ротируется автоматически;
  при необходимости очищайте его вручную или настройте внешнюю ротацию.
- База и логи исключены из git.

Удаление истории: остановите бота и удалите `data/pc_remote.db` — при следующем
запуске база создастся заново.

## Автозапуск (папка «Автозагрузка»)

Бот запускается ярлыком из папки автозагрузки Windows, поэтому он виден в
**Диспетчере задач → Автозагрузка**. Ярлык запускает `launcher.py` через
`pythonw.exe` (без окна консоли), а launcher:

- ждёт, пока `api.telegram.org:443` станет доступен (VPN/прокси может
  подниматься позже Windows);
- запускает `main.py`;
- перезапускает бота через 30 секунд, если тот завершился с ошибкой;
- не допускает второй экземпляр (lock-файл `data/launcher.lock`).

Файл ярлыка:
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\PC Remote.lnk`

Параметры ярлыка:

- Объект: `C:\tgbot\.venv\Scripts\pythonw.exe`
- Аргументы: `C:\tgbot\launcher.py`
- Рабочая папка: `C:\tgbot`

Логи: `logs/launcher.log` (ожидание сети и перезапуски) и `logs/bot.log`
(работа бота).

Проверка: запустите ярлык двойным щелчком — в `launcher.log` появятся строки
`Launcher started` и `Starting bot`, а в `bot.log` — `Starting PC Remote bot...`.
Повторный запуск ярлыка при работающем боте безопасен: второй launcher
завершится с записью `Another launcher is already running`.

Отключить автозапуск: удалите ярлык `PC Remote.lnk` из папки автозагрузки или
отключите его в Диспетчере задач → Автозагрузка.

Автозапуск срабатывает после входа пользователя в Windows (это нужно для
скриншотов и интерактивных окон). Если VPN/прокси включается вручную, бот
стартует автоматически, как только соединение с Telegram появится; до этого
launcher ждёт и пишет попытки в `launcher.log` (не чаще раза в минуту).

## Тесты

Тесты не обращаются к Telegram, не запускают приложения, не выключают ПК и не
используют рабочую базу: все внешние вызовы замоканы, временные БД создаются
в `tmp_path`.

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest -q
```

Покрытие включает конфигурацию и валидацию, безопасность, сбор метрик,
менеджер приложений, профили, базу данных, алерты, фоновый монитор, графики,
сценарии питания и завершения процессов, очистку диска, файловый менеджер и
поиск файлов, буфер обмена, медиа-клавиши, сеть/VPN, уведомления и
планировщик.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Бот не отвечает | Процесс запущен? В `logs/bot.log` есть `Starting PC Remote bot...`? Токен верный? |
| `TelegramConflictError` / `terminated by other getUpdates` | Запущен второй экземпляр. Завершите все `python.exe`, связанные с ботом, и запустите один. |
| «You are not authorized» | Ваш user ID отсутствует в `ALLOWED_USER_IDS`. Проверьте ID через @userinfobot и перезапустите бота. |
| В меню приложения стоит `!` | Путь в **Settings → Applications** (или в начальном JSON) не существует или содержит недопустимые символы. |
| GPU показывает `N/A` | Нет NVIDIA GPU/драйвера, либо NVML недоступен. Остальной мониторинг работает. |
| Температура CPU `N/A` | Датчик не отдаёт данные через psutil/WMI на этом железе. |
| График пустой | История ещё не накоплена (нужен хотя бы один цикл фонового опроса) или диапазон слишком узкий. |
| Алерт по диску `Q:` | Порог заполнения превышен; это ожидаемое поведение. Измените порог в **Settings → Monitoring alerts**. |
| Скриншот не приходит | Заблокирован рабочий стол, либо сессия не интерактивная (бот запущен без входа пользователя в Windows). |
| Clipboard недоступен | Бот запущен не на Windows или буфер обмена занят другим приложением — повторите чтение/запись. |
| Hibernate недоступен | Гибернация отключена в Windows (`powercfg /hibernate on`) или недоступна на этом оборудовании. |
| Изменения в `config/*.json` не применяются | JSON-файлы читаются только при первом запуске. Меняйте настройки в боте или импортируйте бэкап; сброс — **Settings → Backup & restore → Reset to defaults**. |

Для ручной проверки лога:

```powershell
Get-Content C:\tgbot\logs\bot.log -Tail 50
Select-String -Path C:\tgbot\logs\bot.log -Pattern "ERROR|CRITICAL"
```
